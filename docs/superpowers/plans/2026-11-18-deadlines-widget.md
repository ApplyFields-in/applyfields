# Deadlines Widget Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An Android home-screen widget, "Closing soon", in the citizen app. It shows the user's 3 saved opportunities that close soonest, and tapping one opens it.

**Architecture:** `react-native-android-widget` renders a JSX widget from a headless JS task handler. The handler fetches `GET /saved` with the existing `api`/`getToken`, caches the result in a JSON file, and draws from pure functions that compute day counts from `last_date` at draw time. The app asks for a redraw after save/unsave, after an auth change, and when the Saved screen loads.

**Tech Stack:** Expo SDK 58, RN 0.88, `react-native-android-widget@~0.26.0`, `expo-file-system` (File/Paths), Node 24 `node:test`.

**Spec:** `docs/superpowers/specs/2026-11-18-deadlines-widget-design.md`

## Global Constraints

- Android only. On iOS, the web, Expo Go, or anywhere the native module is missing, every widget call is a silent no-op that never throws.
- Only `item_type = 'opportunity'` items with a non-null `card.last_date` that is today or later appear. Never invent or default a date.
- Days come from `last_date` vs. the phone's **local** date when the widget is drawn, never from `days_left`.
- Copy, verbatim: header `Closing soon`. Labels `Closes today` / `Closes tomorrow` / `Closes in N days`. States `Sign in to see your deadlines`, `No upcoming deadlines`, `Couldn't refresh`.
- 3 rows max. `urgent` = days ≤ 3 → colour `C.bad`. Other colours come from `C` in `src/theme.ts`.
- Widget name `Deadlines`. 4×2 cells, resizable `horizontal|vertical`, `updatePeriodMillis: 1800000`.
- Taps: a row opens `applyfields://opportunity/<slug>`, the header and the "no upcoming" state open `applyfields://saved`, and the signed-out state opens `applyfields://login`.
- `android/` is regenerated by `prebuild --clean`. Every native change goes through the `app.json` plugin config, never by editing `android/`.
- Work on a new branch `feat/deadlines-widget` from `main`. Do not touch `feat/razorpay-payments`.

## Review Focus

1. **Signing out, or a different account signing in:** the widget must not keep showing the previous user's deadlines. Sign-out clears the cache and draws the signed-out state (Task 2 test step and Task 4 check).
2. **Timezone off-by-one:** at 00:30 IST the UTC date is still yesterday. `todayLocal` must use local getters (Task 1 test `todayLocal uses local date`).
3. **A saved opportunity whose `card` is null** (unpublished or removed): skipped, never crashes (Task 1 test `skips items without card or date`).
4. **Long titles** (e.g. "Combined Graduate Level Examination 2026 — Tier I…"): one line, end-truncated, never pushing the day label off-screen (Task 2 layout: `maxLines={1}`, `truncate="END"`).
5. **Offline with a cache whose dates have since passed:** past rows drop out at draw time and the next ones roll up, because the cache keeps the full list rather than just the top 3 (Task 1 test `past dates excluded` + Task 2 caching the full `fromSaved` list).

### Task 1: Deadline rules (pure, tested)

**Files:**

**Interfaces:**
- Consumes: `SavedItem` from `@applyfields/types` (type-only import, so Node strips it).
- Produces:
  ```ts
  export interface Deadline { slug: string; title: string; lastDate: string } // YYYY-MM-DD
  export interface DeadlineRow extends Deadline { days: number; label: string; urgent: boolean }
  export function fromSaved(items: SavedItem[]): Deadline[]            // opportunity + card + last_date, sorted asc by lastDate
  export function pickDeadlines(list: Deadline[], today: string, limit?: number): DeadlineRow[] // drops lastDate < today, default limit 3
  export function dayLabel(days: number): string
  export function todayLocal(now?: Date): string                       // YYYY-MM-DD from local getters
  ```
  Day difference is calculated by parsing both strings as UTC midnights and taking `(b − a) / 86_400_000`.

**Interfaces:**
- Consumes: `fromSaved`, `pickDeadlines`, `todayLocal`, `DeadlineRow`, `Deadline` (Task 1). `api.get<SavedList>('/saved')` → `{ data }` and `getToken()` from `@/lib/api`. `C` from `@/theme`.
- Produces:
  ```ts
  // DeadlinesWidget.tsx
  export type WidgetState =
    | { kind: 'signed_out' }
    | { kind: 'rows'; rows: DeadlineRow[] }          // rows.length 0 → "No upcoming deadlines"
    | { kind: 'error' }                              // no cache and fetch failed → "Couldn't refresh"
  export function DeadlinesWidget(props: { state: WidgetState }): React.JSX.Element
  // task-handler.tsx
  export async function loadWidgetState(): Promise<WidgetState>
  export async function refreshDeadlinesWidget(): Promise<void> // Android + module present only; swallows errors
  ```
- `loadWidgetState`: no token → delete the cache file and return `signed_out`. Fetch OK → write `fromSaved(items)` (the full list) to `new File(Paths.document, 'deadlines-widget.json')` and return `rows` from `pickDeadlines(list, todayLocal())`. Fetch fails or throws → if a cache exists return `rows` from the cache, else return `error`.
- `refreshDeadlinesWidget`: `requestWidgetUpdate({ widgetName: 'Deadlines', renderWidget: async () => <DeadlinesWidget state={await loadWidgetState()} /> })`. Guard with `Platform.OS === 'android'` plus try/catch, so Expo Go and iOS don't fail.
- Register with `registerWidgetTaskHandler`. On `WIDGET_ADDED`, `WIDGET_UPDATE` and `WIDGET_RESIZED` it calls `renderWidget(<DeadlinesWidget state={await loadWidgetState()} />)`. Other actions do nothing, because taps use `OPEN_URI`.
- Layout: a `FlexWidget` column filling the widget, background `C.white`, radius 16, padding 12. The header `TextWidget` reads "Closing soon" (navy, bold, 14) with `clickAction="OPEN_URI"` and `clickActionData={{ uri: 'applyfields://saved' }}`. Each row is a `FlexWidget` with `OPEN_URI` to `applyfields://opportunity/<slug>`: title `maxLines={1}` `truncate="END"` (navy, 13) and label (`C.bad` if urgent, else `C.muted`, 12). The state messages are `C.muted`, 13, with taps as in Global Constraints.

### Task 3: Redraw triggers

**Files:**
- Modify: `apps/mobile/src/app/opportunity/[slug].tsx:96-97`. After a successful `api.put` / `api.del` on `/saved/opportunity/${slug}`, call `void refreshDeadlinesWidget()`.
- Modify: `apps/mobile/src/app/(tabs)/saved.tsx`. When `data` changes, run `useEffect(() => { if (data) void refreshDeadlinesWidget(); }, [data])`.
- Modify: `apps/mobile/src/lib/auth.tsx` inside `AuthProvider`. When `signedIn` changes, run `useEffect(() => { if (!loading) void refreshDeadlinesWidget(); }, [signedIn, loading])`. This covers login, OTP, Google, logout and a forced sign-out after a failed refresh. Do **not** put it in `lib/api.ts` `setToken`, because `task-handler.tsx` imports `api.ts` and that would create a circular import.
