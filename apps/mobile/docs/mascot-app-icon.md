# Dynamic mascot app icon

The primary app icon is the ApplyFields logo (`assets/images/icon.png`). For the first 6 hours
after install the launcher keeps the logo; after that it shows the mascot in one of six states,
all alternates baked into the native build.

| State | Shown when | Ends |
|---|---|---|
| `notification` | an unread important alert exists (`closing_reminder`, `admit_card`, `date_change`, `correction_window`, `result`, `saved_item_changed`, `document_expiry`) | the alert is read, or 2 days after it arrived |
| `achievement` | an application-tracker row became `applied`, `selected` or `completed` | 3 days later |
| `sleeping` | no completed session for 7 days | next completed session |
| `thinking` | 3+ research actions in 24 h (search, "eligible only" filter, college search/stream filter, opening a college) | 24 h window passes |
| `active` | a completed session (≥ 30 s in the foreground) within 3 days | 3 days later |
| `default` | nothing above applies (after the 6 h logo period) | — |

Priority is top to bottom. Every number lives in `src/services/mascot/MascotConfig.ts`.

## How it works

| File | Role |
|---|---|
| `src/services/mascot/MascotEventTypes.ts` | icon names, event and state types |
| `src/services/mascot/MascotConfig.ts` | timings, thresholds, which alert types / tracker statuses count |
| `src/services/mascot/MascotActivityTracker.ts` | pure rules: `recordEvent`, `pickIcon`, `canAutoChange` (no I/O) |
| `src/services/mascot/IconManager.ts` | storage, native calls, platform policy, lifecycle hook, Android background task |
| `index.ts` | app entry; loads IconManager first so the background task is defined in headless runs |
| `plugins/without-ios-background-fetch.js` | removes the `fetch` background mode that `expo-task-manager` adds on iOS (unused there) |
| `scripts/mascot-icons.py` | builds per-platform icons from the masters |
| `scripts/mascot-rules.test.mjs` | rule checks (`pnpm --filter @applyfields/mobile test`) |

- Native: [`expo-awesome-app-icon`](https://github.com/oobagi/expo-awesome-app-icon) 2.2.x
  (config plugin in `app.json`). Compatible with SDK 58: it only uses `expo/config-plugins`
  and the Expo Modules API, `peer expo: *`. Pinned `~2.2.1` because it is native code from a
  community package.
- State is a JSON file in the app's document directory (same approach as `lib/offline.ts`).
  On restart the installed icon is read back from the OS, so nothing drifts.
- Signals come from existing calls only: `GET /notifications` (via `refreshUnread` and the
  Alerts screen), `GET /applications` (the tracker the website already writes), the debounced
  search boxes and `AppState`. No new backend endpoint or data.
- Other milestones: call `recordMascotEvent({ type: 'achievement', key: '<unique key>' })`.
- Guard rails: same-icon changes skipped, minimum gap between automatic changes (Android 1 h,
  iOS 24 h; `notification` and `achievement` skip the gap), research events within 1 minute count once, achievements deduped by key, a failed
  change pauses automatic changes for 24 h, ordinary navigation records nothing.

## Platform behaviour and limits

**Android**
- Each icon is a launcher `activity-alias`; `MainActivity` loses its own LAUNCHER filter
  (deep links unchanged). Every change uses `deferUntilBackground`, so native code switches the
  alias only when no activity is visible; the running app is never closed by the launcher.
- Evaluated when the app goes to the background, and by a WorkManager task
  (`expo-background-task`, about every hour, OS decides exact timing). The task is the only way
  `sleeping` can appear, and it also picks up new deadline alerts while the app is closed.
- Launchers can take seconds to minutes to redraw; a few third-party launchers cache icons
  until restarted. On install/update some launchers briefly show a duplicate entry.
- Automatic changes are on by default (switch in Profile → App icon).

**iOS**
- Uses Apple's `setAlternateIconName`. iOS **always** shows a system alert
  ("You have changed the icon for ApplyFields") and there is no public API to change it
  silently, so changes are never silent and never happen in the background.
- Automatic changes are **off until the user turns them on** in Profile → App icon, after an
  explanation. When on: evaluated when the app comes to the foreground, at most once a day.
- `sleeping` therefore can't appear on iOS in practice (the user has to open the app first).
- Dark and tinted home-screen appearances are generated by iOS from the light icon.

**Everywhere**
- Not available in Expo Go or on the web: the native module is absent, calls are no-ops and
  the settings card is hidden.
- Adding or changing icon artwork needs a new native build. EAS Update cannot ship icons.

## Artwork

Masters: `assets/icons/<state>.png` (1024 × 1024). Generated, committed outputs:

- `assets/icons/ios/<state>.png`: 1024², opaque, bezel trimmed.
- `assets/icons/android/<state>.png`: 432² adaptive foreground on transparent, background `#071A43`.
- Themed (monochrome) icon: the existing hood + orb mark, `assets/images/android-icon-monochrome.png`, for all states.

Regenerate after replacing a master: `python scripts/mascot-icons.py` (needs Pillow).

### The current masters are drafts (interim)

They work for testing the system, not for the store:

1. A rounded "app card" with a highlight bezel is baked in. The script trims it, but the
   corners still carry the card's lighter blue (hidden by the iOS mask, visible on square
   Android masks).
2. Soft, upscaled rendering with halo artifacts; a light strip on the bottom edge of
   `achievement`, `notification` and `thinking`.
3. No transparent mascot layer, and the state accents (zzz, bell, star, `?`, motion lines) sit
   in the corners. **Circular Android masks cut them off**, which is the one thing that tells
   the states apart.
4. No usable monochrome per state (a derived silhouette was illegible).

### Final artwork needed (per state, same mascot, same lighting)

- `ios`: 1024 × 1024 PNG, square, opaque, no rounded corners or frame, background `#071A43`
  (or the existing gradient), accent inside the central ~80 %.
- `foreground`: 1024 × 1024 PNG, **transparent**, mascot + accent only, everything inside the
  central 66 % circle (the 66 dp safe zone of a 108 dp canvas). Put it at
  `assets/icons/foreground/<state>.png` and the script uses it as-is.
- Optional `monochrome`: 1024 × 1024, single colour on transparent, same safe zone.
- Optional iOS `dark` and `tinted` variants (add them to the plugin config in `app.json`).

## Build and deploy

```sh
cd apps/mobile
pnpm install
python scripts/mascot-icons.py        # only after artwork changes
pnpm test && pnpm typecheck
eas build --profile preview --platform android   # or ios / production
```

Local: `npx expo prebuild --clean` then `npx expo run:android` (iOS needs macOS). A dev client
is required; Expo Go cannot show alternate icons. Any icon change ships only in a new binary.

## Testing

Automated: `pnpm --filter @applyfields/mobile test` (rules: priority, expiry, dedupe, rate
limit, backoff).

To try states quickly on a device, temporarily lower the timings in `MascotConfig.ts`
(e.g. `minChangeIntervalMs`, `sleepingAfterMs`) in a dev build; do not commit that.

Android helpers:

```sh
adb shell cmd package query-activities -a android.intent.action.MAIN -c android.intent.category.LAUNCHER in.applyfields.app   # which alias is enabled
```

To run the background task now, call `BackgroundTask.triggerTaskWorkerForTestingAsync()` from a dev build.

- [ ] Fresh install shows the ApplyFields logo; after 6 h + leaving the app, the mascot (Android, iOS)

- [ ] Unread `closing_reminder` → bell; read it in Alerts → bell goes at the next change
- [ ] Mark an application "applied" on the website → `achievement` on next resume + leave
